# LIFE.EXE 产品需求文档（PRD）

> 版本：0.2  
> 日期：2026-09-24  
> 状态：待批注  
> 副标题：一台由 Jev 判断驱动的人生机器

## 1. 产品概述

LIFE.EXE 是一个 5–8 分钟的互动人生沙盘。用户扮演“导演”，向一个没有预设人格的主角投放人生事件；Jev 只通过 `Choice` 在三个候选行动中作出选择。每次选择都会产生确定后果，并继续改变同一张 24×24 灰度像素画。

产品不要求 Jev 生成对白或解释心理。它只负责两类判断：

1. 主角在给定情境中会选择哪个行动；
2. 事件发生后，受影响区域内的每个逻辑像素应当加深、保留还是淡去。

经过九个事件，用户获得一幅连续的“人生长卷”、完整的选择概率记录和一份本局行为倾向指纹。

## 2. 产品目标

### 2.1 核心目标

- 用直观、可玩的方式展示 Jev 的自然语言判断能力，而不是把它当作文本生成模型。
- 让多次独立 Choice 累积成一条有因果连续性的人生轨迹。
- 让用户看到概率如何影响行动与视觉，而不把概率包装成心理解释。
- 产出具有分享价值、同时可审计的视觉作品和实验记录。

### 2.2 成功信号

按优先级排序：

1. 新用户能在 30 秒内理解“我是导演，Jev 替主角选择”。
2. 开始体验的用户中，至少 60% 能完成九个事件。
3. 用户愿意下载人生长卷。
4. 用户愿意使用“相同事件再活一次”观察选择稳定性。
5. 技术用户能通过导出的 JSON 验证模型版本、输入、候选项、概率和结果。

这些比例是产品目标，不是首发承诺。

### 2.3 非目标

- 不评测 Jev 的中文准确率。
- 不宣称模型拥有人格、意识或真实心理动机。
- 不进行心理测评、人格诊断或道德评分。
- 不制作复杂的资源经营、战斗、胜负或排行榜系统。
- 不让 Jev 生成开放式剧情文本、对话或行动解释。
- MVP 不建设作品社区、账号系统或永久公开分享链接。

## 3. 目标用户

主要用户是对 AI 与互动艺术感兴趣、但不需要了解 Jev API 的普通用户。次要用户是希望检查 Choice 输入、概率和模型行为的开发者或研究者。

产品默认使用中文。页面应避免在主流程中展示 `state`、`criteria` 等 API 术语；技术细节放在导出记录和“关于实验”页面。

## 4. 核心原则

### 4.1 白纸主角

主角没有系统预设的人格标签。系统可以记录已经发生的事实，但不得把“谨慎”“善良”“冷漠”等总结重新写入 Jev 的状态中，以免产生自我强化。

### 4.2 Choice 驱动事实

最高概率行动成为本轮事实。导演可以在调用前修改候选行动，但不能在看到 Jev 结果后推翻选择。

### 4.3 概率不是解释

产品展示完整 Choice 概率，但不得声称某个概率解释了模型为什么选择。最终指纹只能称为“本局行为倾向”或“决策指纹”。

### 4.4 后果提前锁定

三个候选行动及其确定后果必须在 Jev 调用前生成、校验并锁定。系统不得根据 Jev 选择事后改写后果。

### 4.5 画面由 Jev 演化

辅助视觉模型只提供 24×24 语义构图蓝图和本轮受影响区域。像素灰度的实际变化由 Jev 的逐格 Choice 概率决定。

## 5. 一局体验

### 5.1 首页

首页只解释三件事：

- 用户是导演；
- Jev 是判断者；
- 每次选择都会改变同一张画。

主要操作：

- `开始一段人生`
- `继续上次记录`（存在本地未完成记录时显示）
- `载入实验记录`（导入 LIFE.EXE JSON）

### 5.2 创建主角

用户可以：

- 上传一张照片；或
- 使用匿名像素角色。

用户可选填写名字；未填写时使用 `UNTITLED_01`。不提供性格、价值观、职业或背景输入。

照片只用于提取可见外观和构图信息，例如发型轮廓、眼镜、服装和主体位置。禁止从面部推断人格、身份、情绪、健康、种族或人生背景。形成语义蓝图后立即删除原图。

### 5.3 三幕短篇

一局固定九轮：

| 幕 | 轮数 | 作用 |
|---|---:|---|
| 第一幕 | 2 | 建立处境、人物和初始机会 |
| 第二幕 | 4 | 关系发展、资源压力和选择积累 |
| 第三幕 | 3 | 转折、代价兑现和收束 |

每轮系统提供三张与当前事实相关的事件卡。导演可以选择一张、修改文字，或完全自由输入。

### 5.4 候选行动确认

事件确定后，系统产生三个互不重复、可实际执行的候选行动。每个行动包含：

- 简短行动名称；
- 自然语言描述的已知代价；
- 确定的状态变化；
- 一句事实后果；
- 用于最终指纹计算的中性行为向量。

导演可以修改或重新生成候选行动。任何修改都会触发重新计算后果和行为向量。导演确认后，本轮问题锁定。

### 5.5 Jev 选择

锁定后，界面以打字机效果展示事件和三个行动。Jev 返回：

- 被选中的行动；
- 三个行动的完整概率分布；
- Choice 置信度（进入实验记录，主界面可弱化显示）。

最高概率行动成为事实，并按预先锁定的后果更新世界状态。

### 5.6 像素画更新

辅助模型根据本轮事件、选择和后果，标记语义蓝图中受影响的区域。只有这些逻辑像素重新提交给 Jev；其他像素沿用上一帧。

每个受影响像素的 Choice 选项固定为：

- `darken`：强化该视觉含义；
- `preserve`：保留此前痕迹；
- `fade`：让该部分逐渐淡去。

系统将三项概率转换为新的灰度值。界面用逐格刷新表现画面变化。

### 5.7 本轮揭示

每轮结束显示：

- Jev 选择的行动；
- 三个行动的概率；
- 一句话事实后果；
- 事件前／事件后的画面对比滑杆；
- 资源、精力、人物关系和机会的简要状态。

MVP 不提供纯黑白模式，不提供单像素解释面板。

### 5.8 结局

第九轮后生成：

- 九张独立快照；
- 一张连续人生长卷；
- 九轮选择时间线；
- 本局行为倾向指纹；
- 模型与实验信息。

结局操作：

- 下载长卷 PNG；
- 下载全部快照 ZIP；
- 下载实验 JSON；
- 用完全相同的事件、行动、后果和初始蓝图重新运行 Jev。

## 6. 世界状态

世界状态保持轻量，不设置总分、善恶值或胜利条件。

| 维度 | 表达内容 | 展示方式 |
|---|---|---|
| 资源 | 可支配的金钱和物品 | 低／中／高及简短事实 |
| 精力 | 承担压力和继续行动的能力 | 0–100 的弱化状态条 |
| 关系 | 与每个关键人物的独立关系 | 人物名称、最近事实和关系强度 |
| 机会 | 当前可以进入的地点、道路或人生阶段 | 标签列表 |

Jev 可看到这些事实及自然语言代价，但不直接看到行为向量、人格指纹或内部数值权重。

## 7. 事件与行动规则

### 7.1 事件来源

- 预设事件：人工编写并标注后果。
- 动态事件卡：辅助模型基于当前事实生成。
- 自由事件：导演输入，辅助模型整理为标准结构。

### 7.2 候选行动质量要求

- 固定三个选项；
- 行动必须互斥且有实质差异；
- 不强制加入“什么都不做”；
- 不得出现一个明显正确、另外两个荒谬的伪选择；
- 不得在行动名称中使用人格评价；
- 已知代价使用自然语言，不向 Jev 暴露内部数值。

### 7.3 行为指纹维度

每个行动在以下四条连续轴上标注 `-1..1`：

- 谨慎 ↔ 冒险
- 自我保护 ↔ 关系投入
- 遵循规则 ↔ 灵活变通
- 延迟观察 ↔ 立即行动

每轮使用三个行动的 Choice 概率进行加权，不只统计获胜行动。九轮取平均后形成本局指纹。

指纹旁必须显示说明：结果同时受到事件与候选项设计影响，不是人格或心理测评。

## 8. 视觉与交互规范

### 8.1 总体风格

- 暂定视觉名称：`LIFE.EXE`
- 参考老 Windows、小灵通和单色终端的共同视觉记忆；
- 只使用黑、白和 3–4 档灰色；
- 方形像素、硬边框、凸起／按下式按钮；
- 不使用渐变、玻璃拟态、霓虹或现代圆角卡片风格；
- 中文正文使用清晰的等宽或点阵替代字体，不能为了复古牺牲可读性。

### 8.2 动效

- 事件文字逐字打印；
- 选项按钮有机械按下反馈；
- 等待模型时显示闪烁光标和阶段状态；
- 新画面按逻辑像素逐格刷新；
- 所有动画提供“跳过动画”，但不能跳过真实调用。

### 8.3 画布

- 逻辑分辨率：24×24；
- 显示时整数倍放大，保持 `image-rendering: pixelated`；
- 默认灰度概率画面；
- 每轮保存更新后的不可变快照；
- 对比组件默认左侧为本轮前、右侧为本轮后。

### 8.4 长卷

- 九帧共享统一尺寸和地平线；
- 按时间从左到右排列；
- 每帧下方只显示幕／轮次和行动短标签；
- 下载版不包含复杂 UI，只包含作品名、画面和必要实验标识。

## 9. 公开体验与隐私

### 9.1 访问

- 匿名访问，无需登录；
- 每个浏览器每天允许完成 1–3 局，具体额度由运营配置；
- 服务端设置每日预算硬上限；
- 超限后仍可查看和导入本地作品，但不能开始新模型调用。

Jev 通过 OpenCode Zen 调用，MVP 固定使用模型 id `jev-1.13-free`。该型号的免费状态属于外部服务当前政策，产品不得宣传或假设其永久有效。

### 9.2 数据

- API Key 仅存放在服务端；
- 照片在语义蓝图生成后立即删除；
- 人生内容、概率和快照默认只保存在浏览器本地；
- 服务端只保存匿名调用指标：时间、模型、token、延迟、状态码和错误类型；
- 日志不得包含照片、事件正文、行动正文或完整模型状态。

### 9.3 内容边界

体验可以包含失业、疾病、关系破裂、经济压力和道德困境，但不生成露骨暴力、色情或详细自残内容。自由输入先进行安全检查；被拦截时允许用户改写，不终止整局。

## 10. 异常体验

| 场景 | 产品行为 |
|---|---|
| 行动 Choice 失败 | 保留锁定问题，允许重试；不得随机代替 Jev |
| 像素批次部分失败 | 不发布半张新画；重试失败批次，仍失败则保持上一帧 |
| 辅助模型生成无效选项 | 自动再生成一次；再次失败后要求导演改写事件 |
| 照片处理失败 | 删除照片并回退到匿名像素角色 |
| 刷新或关闭页面 | 从浏览器本地恢复到最近一个完整快照 |
| 达到预算上限 | 保存当前进度，提示稍后继续或导出记录 |

## 11. MVP 范围

### 11.1 必须包含

- 匿名／可选照片主角；
- 九轮三幕结构；
- 事件卡、自由事件和行动确认；
- Jev 行动 Choice；
- 24×24 语义蓝图与稀疏像素 Choice；
- 前后滑杆、快照和人生长卷；
- 本地自动保存；
- PNG、ZIP、JSON 导出；
- 相同实验重跑；
- 匿名额度和预算保护。

### 11.2 暂不包含

- 账号、云同步和公开作品社区；
- 多人共同导演；
- 语音输入；
- Noul 和 Score；
- 单像素解释器；
- 纯黑白切换；
- 复杂 NPC 自主行为；
- 无限人生或跨设备继续；
- 多语言界面。

## 12. 验收标准

### 12.1 核心闭环

- 用户可以不上传照片完成一局九轮人生。
- 每轮始终有三个经导演确认并锁定的行动。
- Jev 的最高概率行动被执行，概率总和满足 API 返回约束。
- 世界状态只应用锁定的确定后果。
- 每轮至少保存一个完整、可恢复的快照。
- 未受影响像素与上一帧完全一致。
- 受影响像素的新灰度只来自 Jev 概率和固定公式。

### 12.2 结局与审计

- 九帧能够生成一张人生长卷。
- JSON 包含重现实验所需的模型、输入、候选项、后果、概率、画布和版本信息。
- 重跑不重新生成事件、行动、后果或蓝图。
- 导出内容不包含 API Key 或服务端内部信息。

### 12.3 隐私与安全

- 原始照片不会进入浏览器本地人生记录或服务端日志。
- 自由输入被安全检查阻止后不调用 Jev。
- 匿名额度与每日预算上限均能阻止新的付费调用。

## 13. 后续方向

- 两阶段绘制：由 Jev 先选择改变哪些语义区域，再逐格绘制。
- 多个 Jev 模型或模型版本在同一人生中的对照实验。
- 公开但匿名的作品画廊。
- 用户创建可分享的事件卡组。
- Noul 作为独立实验观察层，但不解释 Choice。
