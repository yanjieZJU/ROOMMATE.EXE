# 《合租七日 / ROOMMATE.EXE》产品与系统设计

**日期：** 2026-09-28  
**状态：** 已完成对话评审，等待用户书面审阅  
**替代方案：** 本设计替代 LIFE.EXE 的“Jev 逐格生成灰度像素人生画”核心玩法。旧实现保留为技术原型，不再作为产品方向继续优化。

## 1. 产品命题

《合租七日》是一款约 12–15 分钟的实时像素生活模拟。玩家与一个由 Jev 控制的角色搬入同一间公寓，共同生活七天；租约到期时，双方秘密决定继续合租还是搬走。

产品不把 Jev 的 `Choice` 暴露为问卷按钮，也不要求 Jev 生成图像、动画、剧情或动作后果。Jev 只负责在真实可执行的宏动作中作出判断，游戏引擎负责把判断转化为连续、清晰且可验证的行为。

核心表达是：

> 玩家看到的不是模型在回答问题，而是一个角色在生活；它的每个有意义动作背后，都是一次 Jev 判断。

## 2. 目标用户与体验目标

### 2.1 目标用户

- 想快速体验 Jev 与普通文本生成模型差异的开发者和普通访客；
- 喜欢观察型、生活模拟型和涌现叙事游戏的玩家；
- 希望研究结构化判断如何驱动长期角色行为的产品与研究人员。

### 2.2 体验目标

玩家完成一局后应当能够：

1. 明确指出至少三个由 Jev 自主作出的可见行动；
2. 根据共同生活中的证据形成对室友的个人理解，而不是读取系统生成的人格总结；
3. 理解自己的行为如何改变了后续处境，但不能通过可见好感度机械刷分；
4. 在续租揭晓后，通过关键决策记录验证故事确实由 Jev 的 Choice 驱动；
5. 愿意重玩一次，尝试不同的生活方式并比较 Jev 的行动轨迹。

### 2.3 非目标

MVP 不试图模拟完整社会，也不追求开放世界、自由聊天或每次完全不同的生成式剧情。它不是心理测评，也不宣称一次运行能定义模型或人的稳定人格。

## 3. 核心规则与结局

### 3.1 初始角色

Jev 室友使用固定事实背景，便于不同玩家比较同一个初始角色。背景只包含生活事实，例如刚搬到城市、远程工作、经济状况普通、睡眠不规律、带有尚未拆开的物品；不得包含“内向”“善良”“谨慎”等人格形容词。

玩家拥有可直接控制的像素角色。玩家不是上帝，不能修改 Jev 的内部状态、强制其行动或直接写入共同记忆。

### 3.2 七日终点

第七天夜晚，玩家先秘密选择“续租”或“搬走”，随后 Jev 基于七日事实独立完成相同的 Choice。双方卡片同时翻开，得到四种结局：

- 双方续租；
- 玩家续租、Jev 搬走；
- 玩家搬走、Jev 续租；
- 双方搬走。

没有分数、好感度阈值或预写的“最佳结局”。续租只是对共同生活的最终行为判断。

## 4. 核心游戏循环

```text
玩家在公寓中移动并执行动作
→ 世界状态与共同记忆发生变化
→ Jev 完成当前宏动作
→ 引擎识别新的决策点
→ 可行动作解析器生成当前真正可执行的 3–7 个动作
→ Jev 使用 Choice 选择一个动作
→ 引擎播放确定性动画并应用确定性后果
→ 新状态进入下一轮实时生活
```

玩家使用 WASD 或方向键移动，点击物品或 Jev 打开情境动作菜单。移动与简单过渡不调用模型；动作完成、玩家互动、环境突变、身体需求越过阈值或固定事件触发时，才形成新的 Jev 决策点。

Jev 的一个宏动作持续约 4–12 秒。一局预计产生 60–100 次单 `Choice` 判断。任何时刻最多存在一个未完成的 Jev 请求。

## 5. 空间与视觉设计

### 5.1 固定公寓剖面

整栋公寓始终完整显示在单一固定镜头中，不滚动、不跟随、不切换房间：

```text
二层：玩家卧室｜楼梯平台｜Jev 卧室
一层：厨房｜公共客厅｜浴室｜玄关／小阳台
```

剖面结构让两个角色的距离、隔墙等待、关门、共享空间和错过彼此等行为始终可见。房间是连续舞台，而不是菜单入口。

### 5.2 美术方向

- 高密度像素建筑插画；
- 清晰的深色轮廓；
- 奶油色墙面、珊瑚红、暖橙、深青与少量冷蓝；
- 植物、空调、招牌、窗外城市等生活细节；
- 角色比例足以辨认方向、手持物和基础姿态；
- 确定性精灵和动画，不使用 Jev 生成像素。

### 5.3 HUD 与状态表达

HUD 只显示日期、时间和当天已经公开发生的事实，不显示好感度、信任值或续租倾向。

身体状态通过动画或小图标表达：饥饿时关注厨房，疲劳时打哈欠或坐下，压力升高时踱步、停顿或返回私人空间。关系和社会判断完全通过行动表现。

## 6. 世界、角色与物品状态

### 6.1 状态分层

1. **物理状态：** 位置、朝向、饥饿、精力、压力、当前动作；
2. **世界状态：** 时间、房门、食物、物品位置、整洁度、设备状态、访客与事件；
3. **共同记忆：** 已发生且会影响后续判断的结构化事实；
4. **决策记录：** 每次 Jev 请求的状态快照、候选动作、概率、选择、置信度、时间与状态哈希。

物理和世界状态由游戏引擎管理。共同记忆不等于隐藏好感度，它只保存可陈述的事实，例如“玩家在进入房间前敲门”或“Jev 吃掉了桌上唯一一份晚餐”。

### 6.2 可互动物品

MVP 包含约 12–16 个对象：两张床、两扇卧室门、冰箱、灶台、餐桌、沙发、电视、工作桌、浴室、垃圾桶、储物柜、植物、公共留言板以及事件所需设备。

### 6.3 动作定义

每个动作由游戏引擎定义：

- 唯一 id 与可见名称；
- 执行者、目标和目标位置；
- 前置条件与冲突条件；
- 持续时间；
- 确定性状态变化；
- 写入共同记忆的事实；
- 对应动画与中断规则。

MVP 提供约 20–30 个可复用宏动作，覆盖移动、休息、烹饪、进食、清洁、修理、使用或归还物品、敲门、邀请、帮助、拒绝、道歉和退出互动。

## 7. 固定七日事件骨架

每一天约 90 秒，包含清晨、主要活动和入夜。事件直接改变物理世界，不能通过弹窗选择解决。

1. **搬入：** 箱子占据公共区域，需要分配空间并形成第一次边界事实；
2. **最后一份晚餐：** 食物不足，双方可以吃掉、分享、烹饪或购买；
3. **安静的一晚：** 一方必须工作，另一方拥有会制造噪音的活动；
4. **临时访客：** 玩家朋友到访，占用公共空间并改变 Jev 的可行动作；
5. **设备损坏：** 冰箱或热水器故障，需要时间、金钱或忍受不便；
6. **身体不适与停电：** 一人状态下降，同时出现短时停电；
7. **租约到期：** 白天继续正常生活，夜晚完成双方续租判断。

事件采用事实延续而非庞大分支树：未修好的设备继续损坏，未处理的食物会变凉，物品保留位置，冲突不会跨日自动清零。玩家即使不行动，时间和 Jev 生活仍会继续。

## 8. Jev 决策契约

### 8.1 输入

一次动作决策包含：

- 当前日期、时间和公开事件；
- Jev 的位置、身体需求文字等级和当前动作结果；
- Jev 可观察到的房间、角色和物品事实；
- 最近 12 条与当前处境相关的事实；
- 尚未解决的承诺、请求与冲突；
- 当前实际可执行的 3–7 个动作及其已知成本。

每个候选动作都映射到一个由游戏引擎持有的动作 id。Jev 只能返回候选集合内的 id。

### 8.2 输出与执行

MVP 只使用 Jev `Choice`：选择、候选概率和置信度。辅助模型不能替 Jev 选择，Jev 也不能生成动作后果。

游戏在响应成功且状态哈希仍有效时记录完整结果并执行选中动作。若玩家在请求期间改变了关键状态，结果作废并基于新状态重新判断。

第七天的续租决定使用相同契约，候选项固定为“续租”和“搬走”。

### 8.3 记忆选择

共同记忆以结构化事实保存，由确定性规则按照时间、未解决状态、目标对象和当前地点筛选，再渲染为简短自然语言。MVP 不使用另一个模型生成反思、人格总结或日程计划。

## 9. 延迟、失败与恢复

- Jev 在当前动画接近结束时预取下一次判断；
- 等待时播放观察、停顿或整理物品等过渡动画；
- 同一决策使用幂等键；
- 可重试错误使用相同状态自动重试一次；
- 重试仍失败则暂停世界，显示“室友暂时失去回应”，由玩家主动重试；
- 不使用随机动作、辅助模型或付费模型静默回退；
- 浏览器刷新后只恢复最后一次原子提交的完整动作与世界状态。

## 10. 结局与决策记录

续租卡首先以纯游戏形式同时揭晓，不立即显示概率或解释。

揭晓后解锁“七日关键决策”，按时间展示经过筛选的关键节点：

- 当时可观察事实；
- 可执行动作；
- Jev 的选择、概率和置信度；
- 动作造成的确定性后果；
- 该事实后来在哪些决策中再次出现。

系统不生成“Jev 是怎样的人”之类的总结，解释权留给玩家。

## 11. 系统架构

现有 React 应用保留为外壳。Canvas 游戏层负责像素渲染、碰撞、移动和动画；React 负责首页、暂停、情境动作菜单、错误、续租揭晓和决策记录。

核心模块：

1. `SimulationClock`：实时日程和昼夜推进；
2. `EventScheduler`：七日固定事件；
3. `WorldReducer`：唯一确定性世界状态入口；
4. `AffordanceResolver`：依据前置条件生成双方可行动作；
5. `JevController`：状态构建、Choice、幂等与失效响应；
6. `ActionExecutor`：动画、时长和原子后果；
7. `MemoryLedger`：事实索引与相关记忆筛选；
8. `DecisionArchive`：结局后关键决策记录；
9. `SessionRepository`：浏览器本地保存、恢复和导出。

每个模块通过明确数据结构通信。模型提供者、游戏规则和渲染层不得互相直接修改状态。

## 12. 隐私、配额与公开部署

- 游戏不要求照片、账号或自由文本；
- 完整会话与决策记录只保存在浏览器本地；
- 服务端不保存人物行为正文；
- 公开指标只保留 provider、model、问题数、token、延迟、重试和错误码；
- 公开模式沿用匿名 installation 限额、IP 短时限流、单会话并发锁、每日预算和 kill switch；
- Jev 免费模型不可用时暂停，不自动回退到付费模型。

## 13. 测试与验收

### 13.1 自动化测试

- 纯规则测试：日程、动作前置条件、状态后果、记忆筛选、七日推进和结局；
- 模拟 Jev 测试：固定 Choice 序列跑完七天，覆盖四种结局；
- 并发测试：过期状态响应不得提交；
- 恢复测试：刷新只能恢复最后完整动作；
- 端到端测试：移动、物品交互、七日事件、失败重试、续租揭晓和决策记录；
- 真实探针：候选数量、中文状态、延迟、结构完整性和免费模型约束。

### 13.2 产品验收

MVP 必须满足：

1. 新玩家无需阅读 Jev 文档即可在一分钟内移动并完成一次物品互动；
2. Jev 连续十次决策不会选择不可执行动作或破坏世界状态；
3. 正常网络下的模型等待不会出现空白画面或阻断玩家移动；
4. 七天能够在 12–15 分钟内完成；
5. 所有固定事件都有可见环境变化和至少三种合法处理路径；
6. 四种续租组合均可通过模拟 Jev 自动化重现；
7. 决策记录与实际发生动作一一对应；
8. 用户能够通过重玩产生不同轨迹，而不是只看到不同文本。

## 14. MVP 范围外

- 多 Agent 小镇和邻里社会；
- 自由聊天或生成式长对话；
- 随机地图、装修和角色编辑器；
- 多个 Jev 室友或多模型对战；
- 自动生成日程、事件或动作后果；
- 手机触控与联机；
- 账号、排行榜和云端存档。

## 15. 从 LIFE.EXE 原型迁移

### 15.1 保留

- OpenCode Zen / Jev 安全适配器；
- 免费模型固定与禁止付费回退；
- 幂等、重试和稳定错误结构；
- IndexedDB 原子会话仓库；
- 隐私清理导出；
- 公开配额、Redis 失效关闭、内容无关指标；
- 复古像素 UI 的基础排版与控件语言。

### 15.2 替换

- 逐格灰度画布替换为确定性精灵公寓；
- 三选一事件卡替换为实时角色动作；
- 九轮三幕结构替换为七日实时日程；
- 辅助模型事件生成替换为固定事件调度；
- 前后帧滑动比较替换为结局后的关键决策记录。

### 15.3 删除

- 语义像素蓝图；
- 576 格初始化与演化批处理；
- 上传参考照片；
- 生成事件、结构化行动和受影响像素服务；
- 像素概率灰度指纹作为主视觉的产品表述。
