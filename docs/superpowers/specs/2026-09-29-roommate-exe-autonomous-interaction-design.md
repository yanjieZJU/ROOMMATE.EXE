# 《合租七日 / ROOMMATE.EXE》自主交互重构设计

**日期：** 2026-09-29

**状态：** 已完成对话评审，等待用户书面审阅

**关联文档：** `2026-09-28-roommate-exe-design.md`、`ROOMMATE-EXE-PRD.md`、`ROOMMATE-EXE-TECH-SPEC.md`

## 1. 重构目的

现有版本已经能够展示公寓、推进七日时间并调用 Jev，但实际体验仍接近“在固定按钮中观看模型选项”：玩家一次只能围绕一个对象操作；Jev 只获得当前位置附近的一小组静态候选；模型完成判断后，角色没有真正移动；一次无法解析的响应还会暂停整个游戏。

本次重构将产品核心明确为 **Sims 式的单室友生活模拟**：玩家作为室友直接在房屋中生活，Jev 根据自然语言情境选择完整行动意图，游戏把每次选择表现为跨房间移动、物品使用、人物互动和持续后果。

重构后的核心表达是：

> Jev 判断的不是一个弹窗答案，而是此刻要去哪里、做什么，以及如何回应正在发生的共同生活。

本文覆盖旧设计中的核心循环、动作解析、角色执行、失败恢复、交互界面与验收规则。未在本文修改的房屋剖面、七日事件骨架、续租结局、隐私与公开部署规则继续有效。

## 2. 设计原则

1. **选择必须成为可见行为。** Jev 的有效选择必须对应角色移动和确定性动作，不能只写入文字记录。
2. **玩家通过生活行为施加影响。** 玩家不能直接编辑 Jev 的状态、人格或选择。
3. **路径来自状态，不来自预写分支。** 人物位置、资源、耗时、占用、近期事实和模型判断共同产生差异。
4. **模型负责判断，引擎负责事实。** Jev 只选择合法行动 id；寻路、动画、冲突和后果均由游戏规则执行。
5. **模型失败不得冻结生活。** Jev 可以暂时犹豫，但玩家、时间和世界仍然继续。
6. **像素风不能牺牲可读性。** 文字、目标、队列和反馈必须在常见桌面窗口中清晰可辨。

## 3. 核心交互循环

```text
玩家移动或编排行动                    Jev 完成或中断当前行动
        ↓                                      ↓
玩家队列执行：寻路 → 到达 → 动作      引擎生成全屋合法行动
        ↓                                      ↓
世界发生原子后果                     本地规则筛选多样候选
        └──────────── 世界持续推进 ────────────┤
                                               ↓
                                  Jev Choice 选择完整意图
                                               ↓
                                  寻路 → 到达 → 动作 → 后果
```

### 3.1 玩家控制

- 玩家空闲时可用 WASD 或方向键直接移动；直接移动不会调用 Jev。
- 点击任意可达物体或 Jev，显示该目标在当前状态下的动作，而不是把全局交互锁定在一个已选对象上。
- 玩家拥有最多三个动作的队列，可连续安排跨房间行为，例如“去厨房取咖啡 → 走到 Jev 身边 → 递交咖啡”。
- 队列中尚未开始的动作可以取消和调整顺序；当前动作在完成前取消时，不提交世界后果。
- 打开菜单、查看记录和编排队列不暂停时间。

### 3.2 Jev 控制

- Jev 的一个选择是一项完整目标行动，例如“去厨房泡咖啡”或“走到玩家身边询问情况”，移动包含在行动中。
- Jev 在行动完成、行动被中断或世界发生重要变化时重新判断，不按渲染帧或固定短间隔反复调用。
- Jev 和玩家拥有独立执行器，可同时移动和行动。
- Jev 等待响应时继续播放观察、思考或短暂停顿动画，但不伪装成已经作出的选择。

### 3.3 动作生命周期

每个目标动作依次经过：

1. **排队：** 保存动作 id、目标、交互点和创建时所需的前置条件；
2. **寻路：** 计算到目标交互点的网格路径并持续移动；
3. **到达校验：** 再次检查目标状态、占用和动作前置条件；
4. **执行：** 播放有明确时长的动画；
5. **提交：** 通过唯一 `WorldReducer` 原子应用后果、事实和日志；
6. **完成：** 释放占用并触发下一动作或 Jev 新判断。

动作只在第五步产生状态后果。寻路中取消、目标失效或执行完成前中断均不产生半完成状态。后续若需要“烹饪到一半”等玩法，应以独立的阶段动作显式建模，而不是破坏原子提交规则。

## 4. 导航、并发与冲突

### 4.1 导航

- 公寓使用简单的可行走网格和房门连接图；物品提供一个或多个交互点。
- 寻路结果只决定运动轨迹，不改变 Jev 的选择。
- 若目标暂时不可达，执行器先重新寻路；仍不可达时将动作标记为失效。
- 玩家动作失效时显示简短反馈并继续下一队列项；Jev 动作失效时立即形成新的决策点。

### 4.2 占用与竞争

- 选择或排队时不提前锁定物体，避免玩家通过排队长期霸占资源。
- 角色抵达交互点并开始执行时才获得短时占用权。
- 两个角色争用同一物体时，先抵达者执行；后抵达者的到达校验失败。
- 玩家获得明确的失败提示；Jev 将“目标刚被玩家占用”作为新事实重新判断。
- 两个角色可在不同物体上并行行动；只有确实互斥的对象和动作发生冲突。

这种机制让时间、距离和行动顺序成为故事的一部分，而不是用菜单预先禁止可能的冲突。

## 5. 动态行动生成与 Jev 决策

### 5.1 全量合法行动

`AffordanceResolver` 每次从动作目录中解析 Jev 在全屋可完成的目标行动。位置只影响成本和耗时，不再要求目标必须与 Jev 位于同一房间。候选动作必须通过：

- 角色、目标和事件前置条件；
- 目标存在且拥有有效交互点；
- 从当前位置可达；
- 当前世界允许在预计到达时执行；
- 动作不是刚刚无意义重复的行为。

### 5.2 多样性筛选

引擎对全量合法行动进行确定性评分和分组，再选出约 6–8 项交给 Jev。评分只负责让候选集合相关且多样，不能替 Jev 决定最终行为。

评分参考：

- 饥饿、精力、心情和专注等当前需求；
- 距离、耗时、时段和正在发生的事件；
- 玩家最近行为、共同记忆、承诺和未解决冲突；
- 目标是否空闲、资源是否稀缺；
- 行动近期是否重复及是否延续当前计划。

在存在合法项时，候选集合尽量覆盖：满足自身需求、与玩家互动、使用环境、延续计划，以及等待或观察。禁止按固定优先级排序后简单截取前七项。

### 5.3 自然语言快照

Jev 输入包含：

- 当前日期、时间、地点和正在发生的事件；
- 可观察的玩家行为、物品状态和房间事实；
- Jev 当前需求的文字等级；
- 最近相关事实、承诺和冲突；
- 每个候选行动的意图、目标、预计耗时和已知代价。

快照强调情境含义，例如“玩家刚把唯一一杯咖啡放在你的桌上，但没有说话”，而不是只发送数值数组。Jev 返回候选行动 id；移动路径和后果不由模型生成。

### 5.4 决策记录

每次判断保存候选集合、最终选择、可用的概率与置信度、状态哈希和执行结果。主场景只用短暂意图图标表达 Jev 当前目标；完整记录进入不打断游戏的“思绪记录”面板。

## 6. 游戏化状态与连续后果

### 6.1 角色与世界状态

- **角色需求：** 饥饿、精力、心情、专注；
- **房屋状态：** 整洁度、食物存量、噪音以及重要设备状态；
- **关系状态：** 信任与压力两条独立维度；
- **事实记忆：** 已发生的可陈述事件、请求、帮助、冲突和承诺。

信任和压力可以同时上升。例如玩家陪 Jev 熬夜完成工作会增加信任，也可能增加双方压力。关系数值参与规则与候选生成，但不作为可供玩家机械刷分的常驻进度条。

### 6.2 后果链

动作至少影响以下一类结果：可见物品状态、角色需求、房屋状态、关系状态或共同事实。后果必须能改变后续动作的合法性、成本或 Jev 所见情境。

固定七日事件只改变环境和约束，不预写 Jev 的回应。例如“最后一份晚餐”可以因此前食物消耗、人物位置、关系压力和 Jev 判断形成不同轨迹。

### 6.3 七日回顾

第七天仍以双方秘密续租判断结束。结局后提供共同生活记录，展示关键行动、关系变化、房屋最终状态和 Jev 的重要选择，不生成单薄的人格评语，也不把 Jev 定义为某种固定性格。

## 7. 场景与界面

### 7.1 场景表现

- 保留整栋公寓始终可见的像素剖面和固定镜头；
- 玩家和 Jev 至少拥有待机、行走、使用物品、交谈和等待状态；
- 角色位置、朝向、目标和执行进度必须与当前动作一致；
- 咖啡、食物、灯光、垃圾、门和设备等关键后果直接反映在场景中；
- Jev 头顶短暂显示当前意图图标，不用长文本遮挡画面。

### 7.2 操作界面

- 点击物体时在目标附近显示紧凑的情境动作菜单；
- 点击 Jev 时显示当前合法的关系动作；
- 选中另一个目标不会清空已经排队的动作；
- 屏幕底部显示三个动作槽，区分当前动作和后续动作；
- 允许取消与调整尚未开始的动作；
- 思绪记录、连接状态和错误提示位于非模态侧边区域。

中文使用清晰的像素字体或系统无衬线字体。房间名称、物体名称和操作文字必须满足最低字号与高对比度要求；像素滤镜不得应用于文字层。

## 8. Jev 响应适配与降级

### 8.1 宽容解析、严格语义

服务端适配层接受常见的等价格式：直接 JSON、代码块包裹、JSON 字符串、候选序号、动作 id 或准确动作名称。适配后执行严格语义校验：

- 模型仍必须为允许的免费 Jev 模型；
- 最终选择必须唯一映射到当前候选集合；
- 若返回概率，则过滤未知键并按有效候选归一化；
- 概率或置信度缺失不得阻止一个明确且合法的选择；
- 任何响应不得直接携带或修改游戏后果。

### 8.2 恢复策略

1. 首次无法识别时，以相同状态哈希和候选集合自动进行一次格式修复重试；
2. 第二次仍失败时，记录经过清理的失败类型，Jev 执行不改变世界的短暂“犹豫”；
3. 玩家、时间和其他世界行为继续运行，下一决策点自动再试；
4. 连续失败三次后只暂停 Jev 自主控制，显示“Jev 暂时走神了”和“让 Jev 再想一次”；
5. 任一次成功选择都会清零连续失败计数。

不得使用随机动作、辅助模型或付费模型冒充 Jev。浏览器只得到稳定错误类型，不得到 API Key、完整上游响应或服务端提示词。

## 9. MVP 范围

### 9.1 本轮包含

- 简单网格寻路和跨房间目标行动；
- 玩家三个动作的可编辑队列；
- 玩家与 Jev 并发执行和物体到达时占用；
- 全屋合法行动生成与 6–8 项多样性筛选；
- 约 10 个交互目标、15–20 个可见动作和 4 个生活扰动；
- Jev 宽容解析、一次修复重试和非阻塞降级；
- 意图图标、动作队列、思绪记录和可读文字；
- 新状态结构的本地保存、恢复和七日回顾。

### 9.2 本轮不包含

- 自由文本聊天或语言模型生成对白；
- 多角色 Agent、邻居或开放世界；
- 地图扩建、家具摆放、物品制作；
- 模型生成坐标、路径、动画或动作后果；
- 复杂人格技能树和长期跨局养成；
- 手机触控、联机和云端存档。

旧版本存档与新执行器状态不兼容。应用通过存档版本号识别旧结构，并清晰提示开始新游戏，不尝试不安全的半迁移。

## 10. 系统边界

重构后核心职责如下：

- `AffordanceResolver`：解析全屋合法目标行动并完成候选分组与排序；
- `ActionQueue`：维护玩家最多三个动作及 Jev 当前目标；
- `NavigationService`：管理网格、路径和交互点；
- `ActionExecutor`：驱动寻路、到达校验、占用、动画和完成事件；
- `WorldReducer`：唯一原子后果入口；
- `JevController`：决策触发、状态哈希、请求、失效处理和连续失败计数；
- `ZenResponseAdapter`：响应提取、归一化与语义校验；
- `ApartmentScene`：角色表现、物体状态和意图反馈，不直接修改世界规则；
- React 界面：动作菜单、队列、记录和连接状态，通过桥接事件与场景通信。

模型请求期间世界可以继续变化。响应提交前必须重新验证状态哈希或候选依赖；过期结果丢弃并重新判断，不能执行已经失效的动作。

## 11. 验收标准

1. 玩家能点击不同房间的有效目标并连续安排三个动作；
2. Jev 会主动离开卧室，跨房间抵达目标并完成可见动作；
3. 玩家和 Jev 能同时活动，争用同一物体时由抵达顺序产生合理结果；
4. Jev 候选来自全屋当前状态，且不会被固定目录顺序长期限制在同一组；
5. 玩家行为、资源和近期事实会改变 Jev 下一次获得的候选和自然语言快照；
6. 上游格式出现可识别变体时仍能选择；真正失败时玩家和时间继续运行；
7. 连续三次失败只暂停 Jev，并能由玩家触发恢复；
8. 所有已实现动作均遵循“寻路—到达—执行—原子后果”，取消不会留下半完成状态；
9. 七日结束后可从记录中追溯关键行动、世界变化和 Jev 选择；
10. 常见桌面窗口尺寸下，所有重要中文信息无需放大即可阅读。

## 12. 测试策略

- **规则单元测试：** 全屋候选、候选多样性、动作前置条件、队列变更、占用和原子后果；
- **导航测试：** 跨房间路径、交互点、不可达目标和动态阻挡后的重新寻路；
- **控制器测试：** 完成后判断、中断后判断、过期响应和连续失败恢复；
- **响应适配测试：** 标准 JSON、代码块、字符串、序号、名称、缺失概率、未知选择和非法模型；
- **集成测试：** 玩家和 Jev 并发行动、争用物体、动作改变下一候选以及七日持续运行；
- **存档测试：** 只恢复最后一次原子提交，旧版本存档安全失效；
- **浏览器端到端测试：** 编排三个动作、观察 Jev 跨房间行动、模拟响应失败后继续游戏、恢复 Jev、完成七日回顾；
- **视觉验收：** 在目标窗口尺寸检查中文、菜单、队列、角色意图和物品状态的可读性。

## 13. 实施顺序约束

实现必须按依赖顺序推进：先建立动作队列、导航和原子执行器，再重写候选生成和 Jev 控制，随后接入场景动画与界面，最后迁移存档和端到端流程。不得先增加更多按钮来绕过执行器缺失，也不得在没有角色移动的情况下继续扩充 Jev 候选。

每一阶段均先以自动测试定义行为，再完成实现和浏览器验证。完整开发步骤将在本文经用户审阅后另行形成实施计划。
